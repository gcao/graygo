These are copies of timing-only functional benchmark weights, with no trained 80M/independence claim. All 64 benchmark roots and both roles exercise the same selected-policy probe numerical path.

Each complete source group is partitioned into episode setup and complete round waves, including private draws, model work, resolution, score/hash and final output work. Model integrity checks are measured separately; endpoint/block metadata/IO is the disjoint residual. The forecast uses the largest observed wave and setup costs, each group's 200-wave cap, and actual group counts at both registered looks. It never multiplies every game's maximum horizon by a sparse tail's per-game rate. One endpoint uses ceil(500/32)+ceil(1500/32)=63 groups; the pilot's eighteen endpoints use 1,134. Cumulative H_D includes H_P.

The full endpoint metadata residual is budgeted once per endpoint. The entire two-block metadata residual is conservatively budgeted per scientific block, avoiding an assumed steady-state discount. Cold Python/Torch/CUDA startup is measured in a separate original child process. Selected-policy loads are measured three times; ceilings retain two loads/process starts per endpoint, plus one training startup. The scientific/probe forecast retains 2,000 matched blocks / 96k games, 192,512 integrity checks, 768 probe/reproduction forwards, sixty model loads (both scientific looks, archive reloads and probe collection/reproduction) and four cold starts.

All costs use one allocated process/device and the unchanged twofold margin. These are empirical observed-component forecasts, not hardware/runtime bounds. Hash-lane collisions, variable endings and metadata costs remain in actual measured source work. Standalone CPU reporting and unreconciled historical consumption remain separately scoped.
